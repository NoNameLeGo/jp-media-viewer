# Repository Guidelines

## Project Overview
Single-module Android app (Kotlin, Jetpack Compose + Material3) for browsing local images/videos via Storage Access Framework (SAF).
- **License:** AGPL-3.0-only
- **Current version:** beta0.6.1 (versionCode 40)
- **No ViewModel, no DI, no nav component** — all state lives as `remember { mutableStateOf(...) }` inside `MainApp` composable (`MainActivity.kt:98`). Screen routing is an `if/else` on an `isViewing` boolean.
- **No media permissions in manifest** — SAF-only file access. No `READ_EXTERNAL_STORAGE`, `READ_MEDIA_IMAGES`, or `READ_MEDIA_VIDEO`.
- **Material You:** dynamic colors on Android 12+ (`dynamicDarkColorScheme`/`dynamicLightColorScheme`), manual fallback on older versions.

## Architecture & Data Flow
`folder URIs (SAF)` → `MediaScanner` recursion on `Dispatchers.IO` → results serialized to JSON file via `android.util.JsonReader`/`JsonWriter` + metadata in `SharedPreferences` → shuffled for random browse → `MediaViewerScreen`.
- Two screens: `FolderPickerScreen` (home) and `MediaViewerScreen` (viewer).
- `isFavoriteBrowsing` boolean controls favorites-only mode.
- Cache IO on `Dispatchers.IO`; Compose state via `LaunchedEffect`/`DisposableEffect`.
- Videos use Media3/ExoPlayer in `AndroidView` wrapping `PlayerView`. Import alias: `import androidx.media3.common.MediaItem as ExoMediaItem` (avoids name clash with domain `MediaItem`).

## Key Source Files
All under `android/app/src/main/java/com/jp/app/`:
- `MainActivity.kt` — app hub: state, screen routing, cache persistence, theme.
- `data/MediaScanner.kt` — recursive SAF directory scanner with progress callbacks.
- `data/Models.kt` — `MediaItem(uri, name, mimeType, size, folderUri, modifiedAt)` and `AppSettings`.
- `ui/FolderPickerScreen.kt` — folder management, scan status, cache controls, about dialog.
- `ui/MediaViewerScreen.kt` — full-screen viewer: swipe, pinch-zoom, image (Coil), video (ExoPlayer).

## Build & Verification
- **Do NOT run local Gradle builds during agent development.** Use GitHub Actions for verification (`.github/workflows/build.yml`).
- Local build if human-requested: `./gradlew assembleDebug` from `android/` directory.
- **No test suite exists.** CI build is the only verification. Gesture/UI changes need manual device testing.
- Debug APK: `app/build/outputs/apk/debug/jp-media-viewer-{versionName}-debug.apk`

## Release Workflow
After every feature/fix, create a full release:
1. PR merges to `main` (verify CI passes first).
2. Bump `versionCode` (+1) and `versionName` in `android/app/build.gradle.kts` and this file.
3. Update `.github/release-notes.md` with changelog.
4. Commit, tag (`git tag betaX.Y.Z`), push commit then tag separately: `git push origin main && git push origin betaX.Y.Z`.
5. Confirm the tag-triggered CI run started (it builds signed release APK + creates GitHub Release automatically). Do not wait for completion unless asked.
- CI reads release body from `.github/release-notes.md`.

## Media Model
```kotlin
data class MediaItem(
    val uri: Uri, val name: String, val mimeType: String,
    val size: Long, val folderUri: Uri, val modifiedAt: Long
) {
    val isVideo: Boolean get() = mimeType.startsWith("video/")
    val isImage: Boolean get() = mimeType.startsWith("image/")
}
```
